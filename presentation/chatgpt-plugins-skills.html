Source: Plugin architecture

The boundary is the package. A plugin may contain skills, tool connections, or both. A connection is often shown as an app in ChatGPT. Behind the scenes, MCP is the standard used to communicate with a tool server. The server and service may run elsewhere. The plugin does not contain the whole external system.

How are they different?

Custom GPT, skill, and plugin

Think of it as…What you reuseHow you use it
Custom GPT
A named assistant		Its instructions, knowledge files, and configured capabilities.Open or select that GPT, then give it a task.
Skill
A guide		A focused method with supporting materials.Select it, or ChatGPT may choose a relevant installed skill.
Plugin
A backpack		Skills and/or tool connections, bundled together.Install it and use its capabilities in a supported chat.

Source: Moving custom GPT workflows to plugins

These are comparisons of how capabilities are organized, not rankings. Custom GPTs also support workflows and external actions. A plugin does not automatically run for every message. Mentioning one explicitly helps when you want a particular method.

Sources: Workspace sharing, Packaging and distribution

Standalone skills can be distributed as their folder and resources, then installed in a compatible environment. A plugin bundles them for a more convenient installation. File distribution does not copy the creator’s account credentials. Public publication goes through the applicable review process; it is not the same as sending a file.

Source: App access and plugin permissions

Distinguish live source permissions from intentionally packaged reference files. Managed connections may use an administrator-configured identity, so verify who the connection acts as.
